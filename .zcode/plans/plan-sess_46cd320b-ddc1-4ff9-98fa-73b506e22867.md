# 实施计划：MovementTransform 从点变换升级为运动变换

## 目标

把 `MovementTransform` 从 `Func<Vector2, Vector2>`（点变换）升级为 `Func<IParametric<int,Vector2>, IParametric<int,Vector2>>`（运动变换），回归 MapPattern 模式（`mapper: Parameter→Parameter` 的对称）。让变换函数天然获得时间重映射能力（`f(t)↦f(a·t)`、`f(t)↦f(t+Δ)`），无需为"取指定时间点"另造机制。

## 核心设计

| 概念 | 旧 | 新 |
|------|-----|-----|
| `MovementTransform` 委托 | `Func<Vector2, Vector2>` | `Func<IParametric<int,Vector2>, IParametric<int,Vector2>>` |
| 上下文对象 | `TransformScope { Point, Time }` | `TransformContext { Movement, Time }` |
| `Point` | 预存值 | 删除，由 `Movement.Predict(Time)` 现算 |
| `Movement` | 无 | 新增，transform 主入参（对称 MapPattern 的元素 `d`） |
| `Parameter.Transform` | `TransformScope?` | `TransformContext?`（外部 API 不变） |

## 改动清单（按依赖顺序）

### 阶段 1：核心类型

**1. `ViewModel/MovementTransform.cs`**
- 委托签名改为 `Func<IParametric<int, Vector2>, IParametric<int, Vector2>>`
- `MovementTransforms.Identity` 改为 `m => m`
- 更新 XML 注释（运动↔运动，不再"点↦点"）

**2. `ViewModel/TransformScope.cs` → 重命名/替换为 `TransformContext.cs`**
- 删除 `Point`、`Time` 旧定义
- 新类 `TransformContext`，两个字段：
  - `IParametric<int, Vector2> Movement { get; init; }`（被变换的运动本体）
  - `int Time { get; init; }`（新运动当前被采样的时间 t）
- 文件改名 `TransformScope.cs` → `TransformContext.cs`，类名同步改

**3. `ViewModel/Parameter.cs`**
- 字段类型 `TransformScope? Transform` → `TransformContext? Transform`
- `WithTransform(TransformScope)` → `WithTransform(TransformContext)`
- 其余（`Floats`、拷贝构造、`Empty`）不变

**4. 构建验证点**：此时 `MovementMapNode`、`InputPointNode`、`FromPointNode` 会报编译错误（引用旧 `Point`/旧签名），这是预期，阶段 2 修复。

### 阶段 2：收口节点与子图节点

**5. `Nodes/MovementOperator/MovementMapNode.cs`**（改语义，保留为收口入口）
- 收口逻辑改为：求 transform 子图得到 `MovementTransform`（已是运动→运动），直接 `tf(m)` 返回新运动
- 不再构造 `Parametric(t => tf(p))` 的逐帧点变换闭包
- `TransformContext` 注入移到 `FromMovementNode`（见下）

**6. `Nodes/MovementTransform/MovementTransformInputPointNode.cs` → 替换为 `MovementTransformInputMovementNode.cs`**
- 文件/类名改：`InputPointNode` → `InputMovementNode`
- 输出类型从 `Contextual<Vector2>` 改为 `Contextual<IParametric<int,Vector2>>`
- 读法：`dict.Transform?.Movement ?? <零运动>`
- 端口用 `LinqSTGNodeOutputViewModel.Movement(...)`，标题色保持 `NodeColors.TransformInput`（灰）
- 离开 transform 求值返回零运动（`new Parametric<int,Vector2>(_ => Vector2.Zero)`）

**7. `Nodes/MovementTransform/MovementTransformFromPointNode.cs` → 替换为 `MovementTransformFromMovementNode.cs`**
- 文件/类名改：`FromPointNode` → `FromMovementNode`
- 输入端口：接收一个 `Contextual<IParametric<int,Vector2>>` 子图（运动子图，而非点子图）
- 输出端口：`Contextual<MovementTransform>` 不变
- 核心逻辑：返回 `MovementTransform(m => <子图求值结果>)`，其中子图求值时注入 `TransformContext { Movement = m, Time = t }`，`t` 来自新运动的 `Parametric(t => ...)` lambda 参数：
  ```
  return (MovementTransform)(m =>
      new Parametric<int, Vector2>(t =>
      {
          var scoped = dict.WithTransform(new TransformContext { Movement = m, Time = t });
          return inputMovement?.Invoke(scoped)?.Predict(t) ?? Vector2.Zero;
      }));
  ```
  注：输入子图输出的是运动，这里在 `t` 处 `Predict` 它得到点；子图内部若用了 `InputTimeNode`/`InputMovementNode` 会读到注入的 context。

### 阶段 3：衍生子图节点

**8. 新增 `Nodes/MovementTransform/MovementTransformInputTimeNode.cs`**
- 输出 `Contextual<int>`（当前时间 t）
- 读法：`dict.Transform?.Time ?? 0`
- 端口 `LinqSTGNodeOutputViewModel.Int(...)`，标题色 `NodeColors.TransformInput`（灰）
- 供用户拼时间重映射表达式 `a*t`、`t+Δ`（配合 Math 节点）

**9. 新增 `Nodes/MovementTransform/MovementPredictNode.cs`**（movement + time → Vector2）
- 两个输入：`InputMovement: Contextual<IParametric<int,Vector2>>`、`InputTime: Contextual<int>`
- 输出：`Contextual<Vector2>` = `movement.Predict(time)`
- 这是"取指定时间点"的原子节点，也是时间重映射的构件

**10. 构建验证点**：核心类型 + 收口 + 子图入口/出口 + 衍生节点，应能编译通过。

### 阶段 4：时间重映射原语（形态 B 示范）

**11. 新增 `Nodes/MovementOperator/MovementScaleTimeNode.cs`**（`f(t)↦f(a·t)`）
- 输入：`InputMovement`、`InputFactor: float`（a，带 FloatValueEditor）
- 输出：`Contextual<IParametric<int,Vector2>>`
- 逻辑：`new Parametric<int,Vector2>(t => m.Predict((int)(a * t)))`
- `t` 自包含在新运动闭包里，不读 context（形态 B，自包含）

**12. 新增 `Nodes/MovementOperator/MovementShiftTimeNode.cs`**（`f(t)↦f(t+Δ)`）
- 同上，逻辑：`new Parametric<int,Vector2>(t => m.Predict(t + delta))`

## 不在本次范围

- **现有运动算子节点**（Rotate/Scale/Offset/Sum/AfterTime/CartesianToPolar/PolarToCartesian）保持不动。它们已是 movement→movement，与新 `MovementTransform` 签名天然兼容；用户通过 `MovementTransformFromMovementNode` 可把它们包装进 transform 子图。
- **滑动窗口类变换节点**（需要多采样聚合）留作后续。
- **external/LinqSTG 下的 Demo.NodeGraph 项目**（路径 `external/LinqSTG/LinqSTG.Demo.NodeGraph`）不在本次改动范围，它是旧副本/参考实现。

## 风险点

1. **`FromMovementNode` 的 context 注入位置**：`t` 必须在 `Parametric(t => ...)` lambda 内构造 `TransformContext`，这是 `t` 真正存在的地方。若注入位置错误会导致子图读不到当前时间。
2. **递归/重入**：`InputMovementNode` 输出的运动被 `MovementPredictNode` 在某 `t'` 处采样，若 `t'` 回到新运动自身会成环——但这是图编辑器层面禁止的（NN 不允许环），天然安全。
3. **本地化 key 缺失**：实施时需先确认 .resx 里有无 `time` 端口 key，缺则新增。
4. **`MovementTransform` 签名变化波及面**：全局 grep `MovementTransform` 确认除核心文件外无其他消费者（Translator/Parser 等若引用需同步）。
